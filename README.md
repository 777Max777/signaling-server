# Collaborative Editor with Yjs + WebSocket

Веб-приложение для совместного редактирования текста и чата в реальном времени.
Синхронизация построена на CRDT-библиотеке **Yjs**, а обмен изменениями идёт через
собственный **y-websocket** сервер синхронизации.

> Архитектура: клиент-сервер. Все изменения проходят через центральный сервер
> синхронизации (`sync-server/`), к которому подключаются все участники.

## Технологии

- **Yjs** — CRDT-библиотека для синхронизации данных
- **y-websocket** — WebSocket-провайдер для Yjs (клиент)
- **textarea** — простой редактор текста
- **Vite** — сборщик и dev-сервер

Для работы нужны **два** компонента: клиент и сервер синхронизации. Их можно поднять
одной командой через Docker Compose (рекомендуется) или запустить вручную.

## Запуск через Docker Compose (из коробки)

В корне проекта:

```bash
docker-compose up --build
```

Поднимутся оба сервиса:

- **client** — собранный клиент на `http://localhost:3000`
- **sync-server** — сервер синхронизации на `ws://localhost:1234`

Откройте `http://localhost:3000` в нескольких вкладках/браузерах с **одинаковым именем
комнаты**, чтобы увидеть совместное редактирование. Остановка — `docker-compose down`.

## Запуск вручную (для разработки)

### 1. Запустите сервер синхронизации

```bash
cd sync-server
npm install
npm start
```

Сервер поднимется на `ws://localhost:1234`.

### 2. Запустите клиент

В корне проекта:

```bash
npm install
npm run dev
```

Vite откроет приложение на `http://localhost:3000`.

Откройте приложение в нескольких вкладках/браузерах с **одинаковым именем комнаты**,
чтобы увидеть совместное редактирование.

## Возможности

- ✅ Совместное редактирование текста в реальном времени
- ✅ Чат внутри комнаты
- ✅ Переключение между комнатами по имени
- ✅ Отображение количества подключённых участников
- ✅ Автоматическое переподключение (через y-websocket)

## Как это работает

1. **Комнаты** — имя комнаты используется как имя Yjs-документа. Участники с одинаковым
   именем комнаты работают над общим документом.
2. **Синхронизация** — `WebsocketProvider` подключается к серверу `ws://localhost:1234`,
   сервер хранит документ комнаты и ретранслирует sync/awareness-сообщения между клиентами.
3. **CRDT** — Yjs использует CRDT-алгоритмы для автоматического разрешения конфликтов при
   одновременном редактировании.

## Настройка адреса сервера

Клиент вычисляет адрес сервера синхронизации из адреса открытой страницы (`main.js`):

```javascript
const wsProtocol = location.protocol === 'https:' ? 'wss' : 'ws'
const syncUrl = `${wsProtocol}://${location.hostname}:1234`
provider = new WebsocketProvider(syncUrl, roomName, ydoc)
```

Поэтому по умолчанию сервер ожидается на порту `1234` того же хоста, где открыт клиент
(`localhost` или IP в сети). Для другого адреса/порта или для production за reverse-proxy
поменяйте построение `syncUrl` в `main.js`; про WSS/Nginx см.
`sync-server/README.md`.
